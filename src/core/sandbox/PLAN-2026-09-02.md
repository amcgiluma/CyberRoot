## Hitos

### H1 — kill v0: handler, ruido y wiring (1h)
**Qué:** `src/core/sandbox/commands/senal.py` (nombre kill, concepto pendiente `c.kill` no en curriculum aún — solo lo declara README), `KILL_SPEC` con `noise_event("kill")` + eventos `sandbox.signal`. Lógica: parsea `kill [-9|-HUP| -TERM] <pid>...`, default SIGTERM (15). Efectos sobre `fs.processes` (FS mutable):
- SIGTERM/9 → elimina proceso (`fs.processes = tuple(p for p in fs.processes if p.pid != pid)`)
- SIGHUP → reinicia: mantiene PID pero cambia `cmd` (añade ` --reloaded` si no está) y setea `fs.environment[f"HUP_{pid}"]="1"` (visible en `ps`/`env`). Determinista, sin RNG.
Errores GNU honestos:
- sin args → `kill: not enough arguments` exit 1
- pid no numérico → `kill: X: arguments must be process or job IDs` exit 1
- señal desconocida → `kill: invalid signal 'X'` exit 1
- pid inexistente → `kill: (PID) - No such process` exit 1 (por cada pid, acumula stderr `\n`)
- múltiples pids → procesa todos, exit 1 si alguno falló, ruido una sola vez.
Ruido: `NOISE_PROFILE["kill"]=2` en `noise.py` (acción disruptiva > ls, < cp/sudo). Evento signal payload `{pid:int, signal:str ("TERM"|"KILL"|"HUP"), signal_num:int}` type `sandbox.signal` (canal futuro karma), amount 0 para no alterar total_noise.
**Verificación:** `pytest src/tests/core/sandbox/test_kill.py -q` (golden por venir en H2) + `grep -rn kill src/core/sandbox` muestra registro.

- Shell wiring: kill no es wrapper como sudo, es spec normal en registry.
- Curriculum: requires sin `c.cut` (no existe), sin `c.tail` opcional — validado que todos ≤6.
- Generator: no tocar; costura O3↔S2 ya no necesita generator change para que Artorias verifique literatura compartida (registro.csv/purgas.csv/CEBO).
