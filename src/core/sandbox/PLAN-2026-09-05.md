# PLAN-2026-09-05 — S1 sort -k/-t/-n (Smough, lectura VERTICAL)

## Objetivo
Añadir a `sort` de `conteo.py` soporte GNU honesto de `-t` (delimitador, incluido `|`), `-k` (clave por campo) y `-n` (numérico) para que la pista `sort -t'|' -k12 -n purgas.csv | head -n 3` de CENSO-LISTA.md deje de ser lore. Solo el verbo; la quest E3 la pone Seath (T4). Compatibilidad: sin `-k` → salida byte-idéntica a hoy.

## Hitos (~45min c/u) + criterio de hecho

### H1 — Parser de flags `-t`/`-k`/`-n`/`-u`/`-r` (conteo.py _run_sort)
- **Qué:** Extender `_run_sort` para parsear:
  - `-t SEP` / `-tSEP` / `--field-separator=SEP` (SEP single-char; multi-char → `sort: multi-character tab 'SEP'` exit 2; sin arg → `sort: option requires an argument -- 't'` exit 2)
  - `-k KEYDEF` / `-kKEYDEF` / `--key=KEYDEF` (KEYDEF = `F[.C][OPTS][,F[.C][OPTS]]`; F entero >=1; `0` → `sort: field number is zero: invalid field specification '0'` exit 2; opts `n` → numérico por clave; char pos `.C` parseado pero ignorado para ordenar por campo completo - no crashea)
  - `-n` / `--numeric-sort` (global numeric), `-u` / `--unique` (mantener), `-r` / `--reverse` (opcional), soporte combinado `-nu`/`-un`/`-rn` etc.
  - Invalid option → `sort: invalid option -- 'x'` + `Try 'sort --help'` exit 2
  - Sin `-k` → lista keys vacía (fallback a ordenar por línea entera, como hoy)
- **Hecho si:** `sort -t'|' -k2 -n file` no crashea; errores GNU claros; `-k0` da mensaje cero; multi-char tab rechazado; sin `-k` path intacto.

### H2 — Lógica de clave y ordenación
- **Qué:** Implementar `_extract_key(line, delim, key_spec, numeric_global)`:
  - Con `delim is not None`: `parts = line.split(delim)` (conserva vacíos `a||c` → `['a','','c']`); slice `F_start..F_end` (1-indexed, `None` → hasta fin); si `F_start > len(parts)` → `""`; else `delim.join(parts[F_start-1:F_end])` (si `F_end is None` → `delim.join(parts[F_start-1:])`). Char pos `.C` → si presente, `key = key[C-1:]` (substring desde C) o `""` si fuera de rango - no crashea.
  - Con `delim is None` (default blank): `tokens = line.split()` (colapsa whitespace, ignora leading blanks); field N = tokens[N-1] si existe else `""`; rango `N-M` → `" ".join(tokens[N-1:M])` (join con single space) - fallback `""`.
  - Numeric: si `numeric` (global o por-clave `n`), intentar `float(key.strip())` vía regex `^[ \t]*[-+]?(\d+\.?\d*|\.\d+)([eE][-+]?\d+)?` ; si match → `float`; si key vacía → 0.0; si no es numérico → 0.0 (GNU trata non-numeric como 0 en numeric sort). Orden numérico por float, tie-breaker por string original para estabilidad + last-resort `line`.
  - Sort: `sorted(lines, key=lambda l: (tuple(num/string por cada key), l))` estable; `reverse` invierte final; `numeric` sin clave → clave es `float(line)` o 0.
  - Unique: deducir como hoy (tras ordenar, eliminar duplicados por línea completa)
- **Hecho si:** `sort -t'|' -k12 -n purgas.csv` ordena por col 12 numérico; `sort -k2` sin `-t` ordena por token 2; líneas sin columna → `""` → ordenan primero sin crash; `sort -t'|' -k12` con líneas sin `|` → fallback.

## Riesgos
- Diferencia GNU en default blank whitespace (transición blank-to-non-blank) vs split simple → cubrir con test que documenta aproximación; no usado por quest E3 (usa `-t'|'`).
- Char pos `.C` ignorarla puede diferir en tests extremos → implementada como substring, suficiente para no crashear.
- Numeric parse de vacíos/no-numéricos como 0 puede diferir de GNU que usa 0 para non-numeric - verificado con test_gnu2: `a|100` etc con -n whole line dieron order input (todos 0) - nuestro 0 fallback replica.
