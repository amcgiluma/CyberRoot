## S1 — `sudo` GANADO en el sandbox (DESIGN §6.1 forma firmada)
Forma: sin credencial → rechazo diegético accionable que NOMBRA qué falta y
dónde (exit 1, ruido 0: intentar no es delinquir). Con credencial → ejecuta el
comando envuelto, factura ruido PREMIUM (extra sobre el precio base envuelto,
constante documentada) y deja FIRMA en `auth.log` (usuario, comando, tick).
`sudo` NO existe en cap. 0/2 (exit 127, como `ps`/`env` ayer).

Diseño de ejecución: `sudo <cmd>` es un wrapper de orquestación del SHELL
(como las tuberías), NO una spec normal: necesita el registry de la sesión para
despachar el comando envuelto. Se intercepta en `_exec_argv` cuando el nombre
está en el set declarado de la sesión (`available_cmds`). Gate por capítulo:
solo `DEFAULT_CH3_COMMANDS` incluye "sudo" → cap. 0/2 dan 127.

## S2 — Familia conteo: head/tail/sort/uniq («leer con cuidado»)
Comandos normales registrados. Semántica GNU real (DESIGN §2.6.8): goldens
capturados contra coreutils real en la máquina (Ubuntu).
- `head [-n N] [FICHERO...]` → primeras N líneas (default 10); stdin si no hay
  fichero.
- `tail [-n N] [FICHERO...]` → últimas N (default 10); stdin si no hay.
- `sort [-u] [FICHERO...]` → ordena líneas (byte / LC_ALL=C); stdin si no hay.
- `uniq [-c] [FICHERO...]` → colapsa adyacentes (solo adyacentes, sin sort);
  `-c` = prefijo de cuenta alineado GNU. stdin si no hay.
Ruido por el mismo perfil que el resto (⚠️ v1): leer frugal = menos ruido que
un `cat` entero. Family texto. Soportan tubería (ya la digiere el shell).
`tee`/`less` FUERA de hoy (cola P3).
