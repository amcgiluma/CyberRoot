## Hitos (~1h cada)

### Hito 1 — S2 sort --help (GNU-honesto)
**Qué:** Alinear 2 errores de `sort` con coreutils 9.4: `-k0` y `-t` multi-char.
**Dónde:** `src/core/sandbox/commands/conteo.py` — función `_run_sort`, variable `_SORT_HELP`.
**Cómo:**
- Error `field number is zero: invalid field specification '0'` actualmente sin hint. Cambiar a `f"sort: field number is zero: invalid field specification '0'\n{_SORT_HELP}"` o patrón genérico: todo error de campo cero y multi-char tab debe sufijar `\nTry 'sort --help'...`.
- Error `multi-character tab 'ab'` actualmente `f"sort: multi-character tab '{delim}'"` sin hint. Añadir `\n{_SORT_HELP}`.
- Verificar que otros errores que YA tienen hint (`option requires an argument -- 't'`/`-- 'k'`) mantienen hint (no duplicar). Los 2 targets son solo `multi-character tab` y `field number is zero`. Pero si el parse genérico de invalid field también debe llevar hint, añadirlo ahí también (ver test `test_sort_errores_gnu_multi_char_y_k_cero` espera solo substrings, no exactos → seguro añadir hint no rompe).
- Criterio hecho: `sort -k0 f` exit 2 stderr == `sort: field number is zero: invalid field specification '0'\nTry 'sort --help' for more information.` ; `sort -t ab f` stderr == `sort: multi-character tab 'ab'\nTry 'sort --help'...` ; caminos válidos sin cambio de stdout/exit.
- Test: suite 607 → 607 (S2 +0 hasta añadir nuevos tests), luego +2 con nuevos tests de verificación (pero S2 promete 619→621 +2). Los +2 pueden ser tests nuevos, no solo fix. Validar con `pytest src/tests/core/sandbox/test_sort_k.py src/tests/core/sandbox/test_conteo.py`.

### Hito 2 — S1 descubrimiento por lectura (parser hosts)
**Qué:** `cat /etc/hosts` registra hostnames no-localhost en `Shell.hosts` como FS stub.
**Dónde:** `src/core/sandbox/shell.py` — nuevo método `_note_hosts_discovery(cmd, argv, stdout, exit_code)` + hook en `_exec_argv`.
**Interfaces:**
- `HOSTS_PATH = "/etc/hosts"` constante.
- `_parse_hosts_content(text: str) -> list[str]`: splitlines, strip, ignora vacías y `^#`, split whitespace, primer token IP, resto hostnames; filtra `localhost`, `localhost.localdomain`, `broadcasthost`, `ip6-localhost`, `ip6-loopback` (o solo `localhost` mínimo para cumplir AC len==1). Retorna lista única ordenada.
- Stub FS: `FileSystem(root=DirNode(name="/", children={}))` (vacío) o con `/` mínimo. Debe ser serializable via `to_dict`.
- Hook: en `_exec_argv` tras `self._note_credential_read(...)` y tras resolver `result`, si `cmd == "cat"` y `result.exit_code == 0` y alguno de `argv` resuelve a `HOSTS_PATH` (via `self.fs.abspath(arg, self.cwd) == "/etc/hosts"`), entonces invocar `_note_hosts_discovery(result.stdout)`. Solo si exit 0 (si falla GNU-honesto, no descubre). También considerar `cat` sin args leyendo stdin no es caso hosts.
- Descubrir: para cada hostname no existente en `self.hosts`, `self.hosts[hostname] = FileSystem(...)`. No toca `known_hosts` (eso es para ssh). Solo lectura descubre: `ls /etc` no pasa por cat, entonces no descubre.
- Edge: `cat /etc/hosts /etc/hosts` doble → descubre una vez. `cat` con pipe `cat /etc/hosts | grep faro` → la tubería pasa por `_exec_argv` para cada lado; el primer lado es cat y su stdout es el contenido hosts, pero en tubería stdout se usa como stdin del siguiente; aún así el contenido es el del fichero → debe descubrir igual (porque _note_credential_read sí se llama por lado). Mantener mismo comportamiento.
- No descubrir si `/etc/hosts` no existe: `cat /etc/hosts` falla exit 1 con `cat: /etc/hosts: No such file...` → no añadir nada, hosts sigue vacío.
- Costura O↔S: si O3 escribe `/etc/hosts` con `127.0.0.1 localhost` + `10.x.x.x faro`, cat registra `faro` (1 entrada). Si O3 no llega, tests con FS stub con mismo contenido deben pasar.

**Criterio hecho hito 2:** `Shell(fs_con_hosts).execute("cat /etc/hosts")` → exit 0, stdout contiene "faro" y `len(shell.hosts)==1` con clave "faro"; `execute("ls /etc")` no añade hosts; `execute("cat /etc/hosts")` sobre FS sin fichero → exit 1, hosts vacío.
