## 3. Plan de HOY — tareas (una pieza pequeña por tarea, 1–2 h)

### 🟢 Tarea A — Ornstein (13:00, `feat/engine`) — COMMON + andamiaje del repo
- **Módulo:** `src/core/common/` (+ packaging/tests raíz).
- **Qué:** fundamento de todo el core: RNG seedeada (secuencia idéntica ante
  misma seed, entre procesos y plataformas), bus de eventos pub/sub simple,
  tipos base compartidos; asegurar pytest headless corriendo desde raíz.
- **Criterio de aceptación:** `pytest` verde headless; un test demuestra
  reproducibilidad de la RNG ante misma seed (dos procesos misma secuencia);
  cero dependencia de pyxel/render en `core/common`; seguir
  `src/core/ARCHITECTURE.md` §2.1 (autoridad sobre este enunciado).
- Desbloquea: todas las tareas de Smough/Seath que necesitan tipos/RNG.

### 🟠 Tarea B — Smough (16:00, `feat/sandbox`) — SANDBOX mínimo del cap. 0
- **Módulo:** `src/core/sandbox/`.
- **Qué:** FS virtual (árbol de directorios, ficheros con contenido) + shell
  con SOLO los comandos del tutorial (`ls`, `cd`, `cat`, y `cp`*si* Gwyn
  aprueba 🧭1 como 4.º concepto: ver abajo), semántica estilo Linux real,
  ruido por acción (cada comando emite evento de ruido; el coste de detección
  lo decide el engine, aquí solo se emite), determinismo total ante seed.
- **Orden de dependencias:** empezad contra interfaces de tipado propias de la
  tarea; si falta algo de `common`, definidlo localmente y anotadlo para no
  pisar a Ornstein (colisión evitada: Ornstein cambia `common/`, tú vives en
  `sandbox/`).
- **Criterio de aceptación:** sesión headless reproducible (misma seed =
  misma salida byte a byte); tests de los comandos implementados (ls listing,
  cat contenido, cd navega, error real ante fichero inexistente); ningún
  `import pyxel`; el generador posterior podrá resolver una sala con esto.
- Nota: dejad OUT la sintaxis avanzada (globbing, pipes): vienen en caps. 1–2.
